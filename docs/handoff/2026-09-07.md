### 2-2. `has_pre_practice` 컬럼은 `DEFAULT NULL`이 의도다

위 마이그레이션에서 전연습 참석 컬럼을 `DEFAULT NULL`로 둔 것은 실수가 아니다.
**"기록 없음"과 "불참"은 다른 상태**이기 때문이다. `false`를 기본값으로 두면
아직 출석 체크를 하지 않은 대원이 전부 "불참"으로 집계된다.
연습 세트 판정 규칙 자체는 SQL이 아니라 `src/lib/practice-set-rule.ts`에 있다.

### 2-3. 예배 종류 선택지의 단일 출처는 `src/lib/service-time.ts`

과거 `ServiceScheduleForm`과 `ServiceScheduleImporter`가 각자 다른 목록을 갖고 있었고,
특히 Importer에 '기타'가 없어서 OCR이 프리셋 밖 값(`추수감사주일 찬양예배` 등)을 뽑아오면
드롭다운을 한 번 건드리는 순간 원본이 버려졌다. 이제 `SERVICE_TYPE_OPTIONS` 한 곳에서
관리한다. **예배 종류를 추가할 일이 생기면 이 파일만 고친다.**

주의: `POST_PRACTICE_SERVICE_TYPES`(후연습 있는 종류)는 선택지가 늘어도 그대로 두었다.
여기에 종류를 더하면 신입대원 연습 세트 카운팅이 즉시 영향을 받는다.

## 5. Decisions Made

### 편집 UX: "모두 편집 가능" 대신 "요청 시 편집"
전체 인라인 편집을 유지하면서 가로 스크롤을 주는 안도 있었으나 버렸다.
가로 스크롤은 표를 읽는 행위 자체를 망가뜨리는데, 이 화면의 주 용도는 **검토**이고
편집은 소수 행에서만 일어난다. 주 용도를 희생해 부 용도를 살리는 트레이드는 맞지 않았다.

### 편집 중인 행 추적: 인덱스가 아니라 id
후보 셋 중 사용자가 2번(안정적 id)을 선택했다.
- ~~1번 인덱스 추적~~: 삭제 시 인덱스가 밀려 다른 행이 열린다
- **2번 안정적 id** ← 채택. 삭제·정렬로 위치가 바뀌어도 정체성이 유지된다
- ~~3번 삭제 시 패널 닫기~~: 증상만 가리는 회피책. 원인(위치≠정체성)은 그대로 남는다

### 매니페스트: gitignore가 아니라 필드 제거
`public/handoff-manifest.json`을 gitignore하면 diff는 0이 되지만,
`prebuild`가 반드시 돌아야 뷰어가 동작한다는 새 전제가 생긴다.
현재 Vercel 빌드는 그렇게 동작하지만 커밋된 산출물이 주는 안전망을 잃는다.
**결정론적이지 않은 필드만 걷어내면** 커밋은 유지하면서 노이즈만 사라진다.

## 6. Gotchas — 이번 세션에서 실제로 시간을 잃은 곳

### `npm run build`를 dev 서버가 떠 있는 채로 돌리지 말 것
`rowErrorsById is not defined` 런타임 에러가 났는데, **코드에는 문제가 없었다.**
dev 서버와 `next build`가 같은 `.next` 디렉터리를 공유해서 청크가 섞인 것이다
(새 렌더 코드 + 그 변수를 모르는 옛 청크). 스택 트레이스가
`<TableHead>` 줄에서 `Array.map`을 가리키는 **불가능한 조합**이면 이걸 의심할 것.

- 증상 발생 시: dev 서버 kill → `rm -rf .next` → 재기동
- 평소 검증은 `npx tsc --noEmit` + `npm run lint`로 하고,
  **빌드는 서버를 내린 뒤에만** 돌린다

### 이 프로젝트의 테스트 러너는 Jest다 (vitest 아님)
`npx vitest run`을 돌리면 **83개 파일이 전부 실패**하고 "no tests"가 뜬다.
회귀가 아니라 러너 오인이다 — vitest는 `jest.config`의 모듈 매핑(`@/` alias)과
setup 파일을 모르므로 수집 단계에서 터진다. 반드시 `npm test`를 쓸 것.

### 배포 전 체크로 `git diff main develop`가 유용하다
머지 후 이 명령이 **빈 출력**이면 머지 커밋의 트리가 develop과 바이트 단위로 같다는 뜻이라,
develop에서 통과시킨 테스트·빌드 결과를 그대로 신뢰할 수 있다(재빌드 불필요).
